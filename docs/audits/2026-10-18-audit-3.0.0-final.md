# Finaler Audit vor der Auslieferung – metadata-agent 3.0.0 und Webkomponente 3.0.0

Datum: 18.10.2026 · Umfang: **Deep** (alle 12 Dimensionen, risikoreiche Module Zeile für
Zeile) · nur lesend · zusätzlich: Kompatibilität zur Vorgängergeneration 2.1.1 (gleiche
Parameter, gleiche Ansichten).

## 1. Zusammenfassung

Beide Komponenten sind technisch in gutem Zustand: 2.287 Backend-Tests (88 % Coverage),
322 Widget-Specs, ruff/mypy/tsc/helm/promtool sauber, keine Schwachstellen im
ausgelieferten Code. **Kompatibel zu 2.1.1 sind Endpunkte, Parameter, Konfiguration,
Widget-Attribute, Events und alle sieben Ansichten** – im Browser gegeneinander geprüft.
Es gibt aber zwei bestätigte **Kompatibilitätsbrüche im Widget**: Ein Datensatz, den eine
Seite beim Start mit `metadata-input` übergibt, geht verloren, sobald auch `content-type`
gesetzt ist (die mitgelieferte `review-demo.html` zeigt ein leeres Formular), und das in
der README beschriebene Vorgehen „erst `metadataInput`, dann `contentType`“ verliert Typ und
Werte. Dazu kommen ein bestätigter Weg, über Weiterleitungen aus dem Screenshot-Browser die
eigene API auf `127.0.0.1` anzusprechen (S-15), eine leicht auslösbare Blockade der
Verarbeitung durch `/validate` (P-07) und ein veralteter, von keinem Scanner gesehener
Chromium. **Wichtigste Maßnahme:** die beiden Widget-Brüche beheben – sie widersprechen
direkt der Anforderung „nutzbar wie 2.x“.

## 2. Überblick

- **Backend:** FastAPI/Python 3.13, ~17.700 Zeilen in `src/`, ~19.700 Zeilen Tests, Helm-Chart,

  Schreiben ins edu-sharing-Repository, Screenshots per Playwright.
